# MedLink / doctors_check

## Руководство администратора

MedLink — интерфейс для управления учетными записями сотрудников медицинской платформы.

### Возможности

- просмотр общего числа пользователей, активных, ожидающих активации и заблокированных учетных записей;
- поиск по имени и рабочему email;
- фильтрация по роли и статусу;
- добавление пользователя с ролями **Врач**, **Администратор** или **Регистратура**;
- выбор пользователей для групповых действий;
- экспорт списка учетных записей в CSV;
- постоянное хранение учетных записей и профилей в SQLite;
- авторизация администратора по email и паролю;
- разграничение доступа к API по роли администратора.

### Добавление пользователя

1. Нажмите **Добавить пользователя**.
2. Укажите имя и фамилию сотрудника.
3. Введите рабочий email.
4. Выберите роль.
5. Нажмите **Создать пользователя**.

Новая запись появится в начале списка со статусом **Ожидает активации**. В прототипе приглашение только имитируется уведомлением.

### Поиск и фильтры

Введите часть имени или email в строку поиска. Для уточнения списка выберите роль и статус. Кнопка **Сбросить** возвращает все фильтры к исходному состоянию.

### Экспорт

Кнопка **Экспорт CSV** скачивает файл `medlink-users.csv` с именем, email, ролью, статусом и временем последнего входа всех пользователей.

## Запуск проекта

Требуется Node.js 22.5 или новее (используется встроенный модуль `node:sqlite`). Запустите сервер:

```bash
node server.js
```

После запуска откройте в браузере http://localhost:8000.

## Технологические ограничения

- SQLite-файл `medlink.sqlite` создается автоматически и сохраняет профили между перезапусками;
- сессии хранятся в памяти процесса и требуют Redis или другой общей session store при масштабировании;
- действия меню строки и пагинация представлены интерфейсом-заготовкой;
- email-приглашения и аудит действий отсутствуют.

## Изменение профиля

Кнопки **Редактировать профиль** и **Изменить** открывают страницу `/profile.html` с обычной формой. Email доступен только для чтения, а остальные поля проходят серверную проверку и сохраняются в SQLite. После успешного сохранения пользователь возвращается в свой кабинет. Врач изменяет имя, специальность и телефон; пациент — имя.

## Демонстрация видеосвязи

1. Откройте приложение в одном окне и войдите как врач: `anna.krylova@medlink.ru` / `DoctorDemo123!`.
2. В другом окне откройте тот же адрес и войдите как пациент: `elena.smirnova@medlink.ru` / `PatientDemo123!`.
3. Нажмите **Начать ближайший прием** у врача и **Войти в видеоприем** у пациента.
4. Оба окна откроют `/video.html` и увидят общий статус участников видеокомнаты.

Видеомодуль использует реальный WebRTC-медиапоток: браузеры запрашивают доступ к камере и микрофону, согласуют соединение через авторизованный серверный API и передают аудио/видео по зашифрованному DTLS-SRTP-каналу. Также доступны отключение локальных треков и демонстрация экрана.

По умолчанию используется публичный STUN-сервер. Для надежной связи между разными сетями в рабочем окружении настройте собственный TURN:

- `STUN_URLS` — один или несколько STUN URL через запятую;
- `TURN_URLS` (или `TURN_URL`) — один или несколько TURN URL;
- `TURN_USERNAME` и `TURN_CREDENTIAL` — учетные данные TURN.

Камера, микрофон и демонстрация экрана доступны только в безопасном контексте: через HTTPS или на `localhost`.

Редактирование профиля врача доступно в разделе **Мой профиль**: нажмите **Редактировать профиль** и последовательно укажите имя, телефон и специальность. Пациент может изменить имя в разделе **Мои данные**. Изменения отправляются на сервер и записываются в SQLite.

Не используйте прототип с реальными медицинскими или персональными данными без HTTPS, резервного копирования БД, шифрования, аудита и соответствия требованиям к защите медицинской информации.
